# Security and privacy boundaries

Untrusted browser/API input crosses strict Zod/transport schemas and size bounds. Operator endpoints require a hashed high-entropy eight-hour session. Mutations additionally require exact canonical Origin plus session-bound CSRF token. Password checks compare fixed-length SHA-256 digests in constant time. Passwords remain deployment configuration, never stored in SQLite or sent to client components. Cookies use HttpOnly, SameSite=Lax, Path=/ and Secure for HTTPS; login rotates and sign-out revokes them.

Public integration endpoints require no operator cookie. Initiation checks the configured issuer/client/target. Callback consumes a hashed state record atomically before cryptographic verification. Transactions keep original user/client/installation/nonce server-side for five minutes; raw launch references and raw state are never persisted. A callback cannot create an operator session. Any consumed state, even with an invalid JWT or subsequent storage failure, cannot be reused.

Quotas are persistent, deployment-global fixed windows, intentionally independent of spoofable forwarding/IP headers: sign-in 5/minute (successful or failed attempts), public initiation 30/minute, callback 60/minute, JWKS 120/minute, operator launch 20/minute, OAuth scenarios 10/minute. A replay scenario makes two upstream requests within one quota slot. This shared QA tool can be temporarily denied service by consuming a public quota; protect ingress appropriately without blocking legitimate Campus calls. There are no automatic retries.

Requests are bounded before decoding (JSON 16 KiB, form 32 KiB); public query length is capped. Campus HTTP has a five-second DNS deadline, a fifteen-second OAuth request deadline (allowing Campus's app-key retrieval and tunnel latency), and a five-second JWKS request deadline. Responses are limited to 64 KiB, with no redirect following, standard certificate verification and no automatic retries. Only the captured active saved profile (or deployment default) supplies network destinations. Authenticated, CSRF-protected profile mutations may change the selected request base and issuer, subject to the same configuration URL rules and DNS/socket checks. DNS is checked on every request, all resolved addresses are validated, and one validated address is pinned in the socket lookup while preserving TLS hostname validation. Private/reserved/mapped addresses are rejected, except explicit loopback development configuration. Untrusted token jku/x5u fields never supply network destinations. JWKS accepts at most 16 public RSA signing keys with unique explicit kid; private material and unsupported keys are rejected.

Tokens must use RS256. Trusted binding checks run only after signature verification. Time policy requires integer iat/exp, future iat at most 30 seconds, no grace for expiry or future nbf, and exact 300s identity/3600s service lifetime. Roles are an array of strings; the actual Campus contract permits an empty array. Scope grant expectations follow the requested supported scope intersection, not arbitrary operator text.

Pending launches/sessions expire on access and are pruned at startup, writes, quota checks and each minute. Consumed launches are deleted immediately. History reads exclude rows older than 24 hours and return at most 200. Writes prune beyond that bound in the same transaction. Authenticated history contains allowlisted technical IDs and roles; backups and volumes remain sensitive. Raw tokens/assertions/passwords/references/nonces/JTIs and profile claims are absent from history/exports. Nonces exist only in live server-side launch snapshots. Upstream arbitrary text/error descriptions and unknown fields are dropped, not echoed. Numeric rate-limit headers are retained. React escapes all rendered text. JSON export additionally omits decoded claims, request context and full response bodies.

Dynamic responses are no-store. CSP uses a fresh nonce forwarded to the Next renderer with strict-dynamic; no unsafe-inline script allowance. Development alone permits unsafe-eval for Next tooling. Responses also set frame denial, nosniff, no-referrer and HSTS for configured HTTPS. No client telemetry or arbitrary HTML injection is used. Storage failures return generic 500 responses and a fixed safe log marker. Startup failure prevents readiness. Process logs are not a general audit trail; persisted run IDs are the correlation mechanism.

Saved profile names, URLs and registration IDs are non-secret configuration but remain operator-only. The server builds request configuration explicitly; profile bodies cannot alter passwords, public callback origin, signing keys, data paths or the local-HTTP opt-in. Profile context is captured on runs and excluded from exports. See saved-profiles.md for shared selection and callback isolation.

Integration request/response logs are redacted before SQLite persistence, bounded to 500 entries and 24 hours, and accessible only through authenticated no-store APIs. Bodies use explicit protocol field allowlists; raw assertions, access/identity tokens, state, nonce, references, cookies, authorization and arbitrary upstream free text are excluded. Public callback/initiation logging observes the actual inspector response without creating a session. Evidence exports do not include log bodies. See request-logs.md for the complete policy and browser-redirect observation boundary.
